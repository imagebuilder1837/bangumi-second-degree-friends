# 开发

## 环境与验证流程

在仓库根目录执行：

```sh
npm ci
# 修改源码后更新生成产物，再执行完整检查
npm run build
npm run check
```

- 修改 `src/*.mjs` 或 `src/metadata.txt`，由构建生成并提交 `src/index.user.js`；不直接修改生成产物。版本来自 `package.json`，调整时同步锁文件并重新构建。
- `npm run check` 是交付前的完整入口，包含格式、语法、发布一致性、产物可复现性与测试；发现产物过期只报错，不代为生成。只运行行为测试可用 `npm test`。
- 模块入口见 [模块导航](module-guide.md)，预期行为见 [行为规格](spec.md)。

## 浏览器验证边界

自动测试使用 JSDOM、模拟请求、时钟及 IndexedDB，不代表真实浏览器或原站验收。验证生成产物时：

- 通过实际使用的脚本加载方式，在 HTTPS 用户主页验证入口和弹窗；检查浅深主题、窄屏、键盘焦点和滚动。关系子页面不应出现入口。
- 使用小规模关系样本核对模式、扫描、停止、隐藏后重开及刷新后的缓存；跨标签页写入需在真实浏览器单独验证。
- 存储权限、容量失败、原站登录态及限流不由模拟测试证明；不为验证 429 主动冲击原站。原站与浏览器证据边界见 [外部调查](external/bangumi.md)。
