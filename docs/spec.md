# 二度好友发现：行为规格

领域术语见 [GLOSSARY.md](../GLOSSARY.md)。本文规定关系发现、缓存与界面行为；原站结构和浏览器依赖事实见 [外部调查](external/bangumi.md)。

## 关系发现

- 第一跳方向决定中间用户集合，第二跳方向决定从中间用户读取哪种关系。所有模式均排除主页用户；第二跳为好友时排除主页用户的好友，第二跳为反向好友时排除主页用户的反向好友。因此混合模式中的中间用户仍可能成为候选。
- 同一关系列表按用户标识去重，同名但标识不同的用户不合并；重复条目是正常情况，不告警。每位候选的关联人数按不同中间用户计算，重复条目和重试不增加人数；读取失败的中间用户不贡献候选或人数。
- 主动寻找重新读取全部所需关系，不用旧缓存补齐读取失败。主页的第一跳或排除关系读取失败时，不开始扫描中间用户；单个中间用户最终读取失败后继续处理其他用户，但结果标为未完成。
- 仅接受两种跳过：中间用户显示名精确为 `[已注销]`，且关系响应是指定原站“页面被吃掉”错误页时，跳过整个列表，不贡献候选或人数，主页关系不适用；页面身份及列表结构合法、标准用户条目的同源链接精确指向 `/user/`（无查询和片段）时，跳过该条目，保留其余有效关系，并按列表记录缺失用户标识的条数。其他错误仍属失败，不能因错误已知而自动容错。
- 缺失用户标识的容错同样适用于主页第一跳和排除关系，两者均继续扫描。已接受的缺失可能少发现关联，或使本应排除的直接关系成为候选；不推测缺失身份、不以旧缓存补齐。仅有成功和跳过时按既定规则视为完成，正常颁奖和保存；完成不保证原站数据无缺失。

## 读取与取消

- 仅在受支持域名的 HTTPS 用户主页挂载入口；主页身份和关系链接须匹配当前用户标识。读取使用同源凭据，关系页面的身份、链接与列表结构须通过校验。响应最终 URL 与请求 URL 不一致、身份不符或无法识别的列表均属于失败，不能当成空关系；已接受的跳过也不表示空关系。此检查不代表浏览器不会跟随重定向。
- 瞬时网络或正文读取错误、超时、HTTP 408 与 5xx 有限重试；其他客户端错误、跳转与解析失败不重试。503 的有效 `Retry-After` 约束重试等待下限。
- 停止或收到 429 时，取消当前扫描的在途请求和重试等待，不再调度后续关系读取；保留已展示的部分结果，晚到响应不能继续更新结果。429 使用有效的 `Retry-After` 确定冷却截止时间，缺失或无效时采用默认冷却。
- 扫描、停止和冷却状态仅属于当前页面实例，不跨标签页共享；同一页面不并行运行多个扫描，旧缓存读取也不能覆盖较新的模式或扫描结果。

## 缓存

- 缓存保存关系快照，而非某模式的最终排名；查询时按所选模式重建结果。主页的第一跳、排除方向，以及所有第一跳中间用户的第二跳快照必须齐全，才展示完整缓存。相同方向共用快照；缺失代表未知，显式空集合可以完整。
- 快照不按年龄过期，可以跨扫描和模式组合不同时间取得的观察。“完整”仅指所需快照齐全，不保证实时性或同一时刻的关系图。
- 整张列表不可访问的跳过按用户和方向保存独立标记及观察时间，不伪装成空关系；标记可满足中间用户的第二跳缓存依赖，但不能代替主页关系。部分条目缺失的快照保存有效关系、缺失条数及观察时间，可满足主页或中间用户依赖；载入后重建相同跳过原因和详情。两类观察与正常快照按同样的时间合并规则相互替换；主动寻找仍重新请求，不以旧关系补齐跳过。
- 只有完整扫描（含仅有跳过而无失败的扫描）才尝试整体提交；失败、停止或限流不保存本次暂存结果。保存失败保留旧缓存和已完成的实时结果，扫描完整与保存成功分别表达。
- 同源并发写入在事务内读取最新缓存后合并，保留无关用户及方向；按观察时间保留较新快照，相同时间允许后提交者替换。写入失败或事务完成前取消时整体回滚。其他已打开页面的结果不因缓存写入而自动刷新。

## 信息层级

- 顶部依次为“开始寻找”、四种关系模式下拉框、关闭按钮 ×，不重复展示大标题或“模式”标签。
- 操作区与状态区固定，候选用户列表独立滚动。“详情”位于状态区，默认折叠，无记录时隐藏。内部先展示全部失败，再展示全部跳过，空组隐藏，组标题显示数量；每项左侧是小头像和昵称主页链接、关系方向，右侧为右对齐的简要原因，不展示 HTTP 状态码；缺失条目记录在列表所属用户名下，原因包含缺失条数。主页关系读取失败也进入详情，缓存读写错误仅在顶部提示。
- 详情沿用灰字箭头、浅底细边框、原站链接色，失败组标题使用克制的警示色；内容限高并独立滚动，避免挤占候选列表。窄屏原因移至下一行右对齐，昵称允许换行，不出现弹窗内横向滚动。扫描更新保留展开状态及已聚焦的详情链接，停止和限流保留已展示的详情；新扫描和切换模式清空并折叠。折叠详情内的链接不参与键盘焦点循环。
- 视觉沿用 Bangumi 的紧凑排版、链接色与明暗主题；“开始寻找”使用粉底白字，不取代排名配色。脚本入口及弹窗控件仅在键盘操作时显示焦点框；鼠标点击、触摸或鼠标移动悬浮后隐藏焦点框，但不移除实际焦点。鼠标操作引起的程序化焦点转移也不显示框。
- 候选摘要行依次为框内序号、头像与昵称、关系说明、展开按钮。序号放大，以摘要行垂直居中；展开头像区不改变序号的对齐基准。
- 按关联的中间用户人数降序排列，同分按用户标识字符串升序。扫描期间序号为临时排名；只有完整结果（含完整缓存结果）的前三名使用金银铜底色。

## 关系说明

A 代表主页用户，实际显示其昵称（普通文字，不添加主页链接）；TA 指该行候选用户；N 为实际关联的不同中间用户人数。

| 模式 | 文案 |
| --- | --- |
| 好友的好友 | A 的 N 位好友加了 TA |
| 好友的反向好友 | TA 加了 A 的 N 位好友 |
| 反向好友的好友 | A 的 N 位反向好友加了 TA |
| 反向好友的反向好友 | TA 加了 A 的 N 位反向好友 |

不使用“贡献者”作为界面称呼。展开区仅展示被计入人数的中间用户头像，悬停可查看昵称；不重复添加解释性占位文案。

## 展开与浏览

- 默认全部折叠，允许多行同时展开。独立的“展开 / 收起”按钮附方向箭头；用户头像和昵称链接不触发展开。
- 用户链接在新标签页打开。展开和加载更多仅浏览已有结果，不发起关系请求。
- 候选每批展示 50 条，中间用户头像每批展示 40 个，两处均以“显示更多”继续加载；全部显示后移除对应操作。追加时保留已有项及当前阅读位置，不滚动追随移到底部的按钮；从按钮触发时，键盘焦点接续到首个新增项。
- “显示更多”采用透明底、无常驻边框的灰字细下箭头；它与“展开 / 收起”共用“详情”的悬浮效果，仅文字加深并以半透明背景叠色（浅色主题黑色、深色主题白色），保留卡片原底色，不变蓝、不新增外框。候选列表的操作为卡片下方的居中整行点击区；头像区的操作独占末行并靠右，不混排在头像中，不固定或遮挡内容。
- 实时重排保留每个候选的展开状态及已加载批次；新扫描或切换模式重置这些状态。

## 状态与进度

- 状态提示统一显示在顶部，候选列表区域仅展示结果，不重复显示加载、错误或空结果提示。

- 打开时读取缓存，不自动扫描；缓存摘要显示“已载入缓存 · N 位候选用户”（有跳过时追加异常关系读取项数），不展示快照时间范围。
- 扫描总数未知时显示“正在获取主页关系”，进度条不显示虚构百分比；总数确定后显示“扫描进度：X/Y”及进度条。X 为已处理的中间用户数，包含成功、失败和跳过，并分别说明人数（无跳过时省略跳过项）。含缺失条目的中间用户计入跳过，仍贡献有效关系，不重复计入成功；主页异常只进入详情，不计入中间用户进度分母。
- 完成后显示候选人数；完整扫描无候选时显示明确的空结果，而不是再次开始的提示。实时及缓存结果若有跳过，状态追加“跳过 N 项关系读取异常”；项数按所属用户和方向计算，不等于丢失的用户数或中间用户进度中的跳过人数。
- 处理进度达到总数不代表结果完整。失败、停止、限流及缓存保存失败必须直接显示，不隐藏在详情中；失败或停止的结果标明未完成。
- 寻找期间主按钮切换为“停止寻找”，模式不可切换。限流冷却结束后须手动重新开始。
- 关闭或 Escape 仅隐藏弹窗，不停止缓存处理或扫描；隐藏期间暂停候选和详情的绘制，重新打开时展示最新结果，保留当前模式、进度与浏览状态，不重复读取缓存或补画中间结果。离开页面终止未完成请求。
